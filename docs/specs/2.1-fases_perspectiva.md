## 📋 RESUMEN EJECUTIVO

### Visión
Sistema web para gestión de inventario físico escolar con desarrollo **progresivo** (Local → Docker → Producción) y **código limpio** verificable en cada incremento.

### Stack Definitivo (No Negociable)

**Backend:**
- Python 3.13.0
- Django 5.2 LTS
- Django REST Framework 3.16.1
- PostgreSQL 16.6
- Simple JWT 5.4.0

**Frontend:**
- Node.js 22 LTS
- Next.js 16.0.3 (App Router + Turbopack)
- React 19.2 + TypeScript 5.7
- Zustand 5.0.3 (estado global)
- TanStack Query 5.61
- Tailwind CSS 3.4.17 + shadcn/ui (DEFINITIVO desde MVP)

### Alcance por Fases

| Fase | Duración | Entregables Clave |
|------|----------|-------------------|
| **Fase 0** | 1-2 días | Estructura de proyecto + configuración entornos |
| **MVP** | Semana 1-2 | CRUD ítems + Catálogos + Auth + Import/Export Excel |
| **MVP+** | Semana 3 | ⭐ Modal edición masiva (PRIORIDAD) + Batch operations |
| **Post-MVP** | Semana 4+ | Vistas especializadas + Historial UI + Permisos + QR |

#### item.py (Modelo Principal)
```python
from django.db import models
from django.core.validators import MinValueValidator, MaxValueValidator
from django.core.exceptions import ValidationError
from decimal import Decimal

class ItemInventario(models.Model):
    """Modelo principal de ítem de inventario"""
    
    codigo = models.CharField(
        max_length=50,
        unique=True,
        db_index=True,
        help_text="Código único del ítem"
    )
    ubicacion = models.ForeignKey(
        'Ubicacion',
        on_delete=models.PROTECT,
        related_name='items'
    )
    responsable = models.ForeignKey(
        'Responsable',
        on_delete=models.PROTECT,
        related_name='items'
    )
    articulo = models.ForeignKey(
        'Articulo',
        on_delete=models.PROTECT,
        related_name='items'
    )
    cantidad = models.IntegerField(
        default=1,
        validators=[
            MinValueValidator(1),
            MaxValueValidator(9999)
        ]
    )
    valor_unitario = models.DecimalField(
        max_digits=15,
        decimal_places=2,
        default=Decimal('0.00'),
        validators=[MinValueValidator(Decimal('0.00'))]
    )
    fecha_adquisicion = models.DateField(null=True, blank=True)
    estado = models.CharField(
        max_length=20,
        choices=EstadoItem.choices,
        default=EstadoItem.ACTIVO
    )
    observaciones = models.TextField(blank=True, default='', max_length=500)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
    
    class Meta:
        db_table = 'inventario_item'
        ordering = ['-created_at']
        indexes = [
            models.Index(fields=['codigo']),
            models.Index(fields=['ubicacion', 'estado']),
            models.Index(fields=['responsable', 'estado']),
            models.Index(fields=['estado']),
        ]
        constraints = [
            models.CheckConstraint(
                check=models.Q(cantidad__gte=1),
                name='cantidad_minima_uno'
            ),
        ]
    
    @property
    def valor_total(self):
        return self.cantidad * self.valor_unitario
    
    def clean(self):
        super().clean()
        if self.codigo:
            self.codigo = self.codigo.upper().strip()
        if self.ubicacion and not self.ubicacion.activo:
            raise ValidationError({'ubicacion': 'Ubicación inactiva'})
        if self.responsable and not self.responsable.activo:
            raise ValidationError({'responsable': 'Responsable inactivo'})
```

## ⚙️ REQUERIMIENTOS FUNCIONALES CLAVE

### 1. Autenticación JWT

**Endpoints:**
- `POST /api/v1/auth/login/` - Login con email/password
- `POST /api/v1/auth/refresh/` - Renovar access token
- `POST /api/v1/auth/logout/` - Invalidar refresh token

**Flujo Frontend:**
1. Usuario ingresa credenciales
2. Validación con Zod
3. POST a /login/
4. Almacenar tokens en Zustand
5. Redirigir a /dashboard
6. Interceptor agrega header `Authorization: Bearer <token>`
7. Auto-refresh 5 min antes de expirar

### 2. CRUD de Ítems

**Endpoints:**
- `GET /api/v1/inventario/items/` - Listar (paginado)
  - Query params: `page`, `page_size`, `search`, `sede`, `ubicacion`, `responsable`, `estado`, `ordering`
- `POST /api/v1/inventario/items/` - Crear
- `GET /api/v1/inventario/items/{id}/` - Detalle
- `PUT/PATCH /api/v1/inventario/items/{id}/` - Actualizar
- `DELETE /api/v1/inventario/items/{id}/` - Eliminar

**Validaciones Backend:**
- `codigo`: único, máx 50 chars
- `cantidad`: 1-9999
- `valor_unitario`: >= 0
- `fecha_adquisicion`: no futuro
- Relaciones deben estar activas

**Frontend:**
- Tabla con filtros avanzados
- Búsqueda en tiempo real (debounce 300ms)
- Paginación: 50 ítems/página
- Formulario con validación Zod

### 3. Importación/Exportación Excel ⭐⭐⭐

**CRÍTICO:** Feature más compleja del sistema

#### Exportación
- `GET /api/v1/inventario/items/export/`
- Respeta filtros activos
- Formato: `.xlsx` con openpyxl
- Columnas: Código, Sede, Ubicación, Responsable, Artículo, Cantidad, Valor, Estado, etc.

#### Importación
- `POST /api/v1/inventario/items/import/`
- Validación exhaustiva por fila
- **Auto-creación de Artículos** si no existen
- Transacción atómica (todo o nada)
- Reporte detallado de errores

**Flujo de Importación:**

```
1. Usuario sube archivo .xlsx
2. Frontend valida: extensión, tamaño < 5MB
3. Backend lee con pandas
4. Validar cada fila:
   - Código único
   - Sede existe
   - Ubicación existe en esa sede
   - Responsable existe
   - Artículo existe O datos para crearlo
   - Cantidad 1-9999
   - Valor >= 0
5. Si HAY ERRORES → Retornar reporte detallado (fila + campo)
6. Si TODO OK:
   - Auto-crear artículos faltantes con get_or_create()
   - Crear/actualizar ítems
   - Crear historial con tipo='importacion'
   - Retornar reporte éxito
```

**Estructura Excel Requerida:**

| Columna | Tipo | Requerido | Notas |
|---------|------|-----------|-------|
| codigo | string | Sí | Único |
| sede_codigo | string | Sí | Debe existir |
| ubicacion_nombre | string | Sí | Debe existir para esa sede |
| responsable_documento | string | Sí | Debe existir |
| articulo_codigo | string | Sí | Se crea si no existe |
| articulo_nombre | string | Sí* | *Si artículo no existe |
| articulo_categoria | string | Sí* | *Si artículo no existe |
| cantidad | int | Sí | 1-9999 |
| valor_unitario | decimal | Sí | >= 0 |
| fecha_adquisicion | date | No | YYYY-MM-DD |
| estado | string | Sí | Valor válido de enum |
| observaciones | string | No | Máx 500 chars |

### 4. Edición Masiva ⭐⭐ (MVP+ - PRIORIDAD ALTA)

**Endpoint:**
- `PATCH /api/v1/inventario/items/batch-update/`

**Body:**
```json
{
  "updates": [
    {"id": 1, "ubicacion_id": 15, "cantidad": 2},
    {"id": 2, "responsable_id": 5, "estado": "mantenimiento"},
    ...
  ]
}
```

**Frontend:**
- Componente `ItemBatchEditModal.tsx`
- Librería: `react-data-grid`
- Grid editable tipo Excel
- Columnas editables: Ubicación, Responsable, Cantidad, Valor, Estado
- Columnas read-only: Código, Artículo, Sede
- Validación por celda en tiempo real
- Highlight de celdas modificadas
- Confirmación antes de guardar

**Flujo:**
1. Usuario selecciona 2+ ítems (checkboxes)
2. Click "Editar seleccionados"
3. Modal con grid editable
4. Usuario modifica celdas necesarias
5. Click "Guardar Todo"
6. Confirmación: "¿Guardar cambios en X ítems?"
7. Backend procesa en transacción
8. Historial se crea por cada ítem modificado
9. Toast de éxito

### 5. Gestión de Catálogos

CRUD completo para:
- Sedes
- Ubicaciones (filtradas por sede)
